# Decisions

Each entry: decision, why, alternatives considered. Newest at the bottom.

## D1. Repo location is the Orca-registered folder
- **Decision:** Use `/Users/hutchida/orca/projects/meeting-prep-agent` (already a git repo registered in Orca) instead of `~/GIT/meeting-prep-agent`.
- **Why:** Orca worktree/agent orchestration needs a registered repo; it is already a fresh local git repo with no remote.
- **Alternatives:** Create `~/GIT/meeting-prep-agent` and register it with `orca repo add` (extra moving part, no benefit).

## D2. LLM model: no Claude Haiku alias exists on the proxy
- **Decision:** `LLM_MODEL` has no Haiku default. The proxy `/models` lists no Haiku alias (Claude entries are Sonnet 4/4.5/4.6/5 and Opus 4.7/4.8 on Vertex). The default is the cheapest tool-calling model that passes measurement in G0b, with `vertex-ai-gemini-3-flash-preview` as the pre-measured candidate (tool calling works, ~1.4 s for a tiny call). Configurable through `LLM_MODEL`.
- **Why:** The $0.05/briefing and 60 s targets are not realistic with Sonnet-class pricing across four sub-agents; a Flash-class model is the nearest in price/latency to Haiku.
- **Alternatives:** `vertex-ai-claude-sonnet-4.6` (works, costs several times more); ask the user (not blocking). Swap by changing one env var.

## D3. Credentials handled locally, never committed
- **Decision:** `LITELLM_BASE_URL` / `LITELLM_API_KEY` were not present in the orchestrator's shell. They were supplied in the build prompt. They are kept only in a gitignored `.env` (mode 600) in the repo root and copied into each task worktree's gitignored `.env`; they never appear in task prompts, reports, recordings, traces or commits.
- **Why:** Workers launched by Orca do not inherit the user's interactive shell environment.
- **Alternatives:** Put them in `~/.zshrc` (changes the user's shell config, not requested).

## D4. Worker agent and model
- **Decision:** Workers run as the `opencode` agent with `github-copilot/claude-sonnet-5.5` (test call confirmed OK). Token/cost metrics may be "unavailable" if the harness does not expose them.
- **Why:** Same signed-in account as the orchestrator; strong coding model.
- **Alternatives:** `claude` CLI agent (not tested for account/billing).

## D5. Python type checker is mypy; web lint uses plain typescript-eslint
- **Decision:** `mypy --strict` for agent/, flat-config ESLint with typescript-eslint for TS.
- **Why:** Simple, offline, no node download (pyright's pip wrapper fetches node).
- **Alternatives:** pyright; eslint-config-next.

## D6. Pydantic models for the contract live in agent/src/mpa/contract/ and are owned by the contract task
- **Decision:** G0b owns `agent/src/mpa/contract/**` (Pydantic models mirroring the JSON Schema) plus `agent/tests/test_contract*.py`.
- **Why:** The contract has a single owner; service tasks import, never redefine, models.
- **Alternatives:** Each service task writes its own models (drift risk).

## D7. Model default after measurement
- **Decision:** `LLM_MODEL` default is `vertex-ai-gemini-3-flash-preview` (fallback `vertex-ai-gemini-3.6-flash`), from `docs/orchestration/measurements.md`: tool calling works, 1.4–1.8 s per call, about US$0.50/$3.00 per 1M tokens in/out, no rate limits seen with 6 concurrent calls. The LLM client omits `temperature` for models that reject it and uses `reasoning_effort: minimal` where thinking tokens would eat `max_tokens`.
- **Why:** Cheapest reliable tool-caller; Claude models on the proxy cost 5–10x more per token. No Haiku alias exists.
- **Alternatives:** `azure/gpt-5-mini` (cheaper per token, rejects `temperature`, slower); Sonnet-class (over the $0.05/briefing target).

## D8. Contract design choices made in G0b
- Timestamps are `YYYY-MM-DDTHH:MM:SS[.sss]Z` (UTC, `Z` only); `Settings` normalises `DEMO_NOW`.
- Email sender field is `sender`. Citations and search hits are one object per type so the id prefix is enforced by schema. Pack sections are a fixed 7-tuple. `Sentence` = `FactSentence` (≥ 1 citation) or `NoteSentence` (`kind: "note"`).
- `ToolResult` = `{items, total_matches, truncated}`; a `get_email` body over 4 KB is truncated by the tool layer with `truncated: true`.
- Generated `models.py` is committed and regenerated by `agent/scripts/gen_models.py` (tested for drift). No hand-written mapping layer exists, so "field only in a mapping" is covered by schema/model/fixture property-set equality tests.
- Enron items keep original dates and real corporate addresses (public CMU release, noise only); synthetic items use `.test` domains.

## D9. How the finished briefing reaches clients (gap found at the G0 gate)
- **Decision:** The 8 KB event cap means a full `BriefingPack` can't travel in one event, and the contract had no way to deliver the final pack. A follow-up contract task (g0c) adds an `assemble_pack(events)` helper (TS + Python) and a fixed event order: `… verifier_result`, then one `draft` event per section (seven, canonical order, only the last has `complete=true`), then `run_done`. Only verified sentences are ever emitted. Full-run event-stream fixtures are added for UI/API/eval development.
- **Why:** Keeps the API to the three specified routes, keeps the UI honest (it never shows unverified text) and gives every consumer one tested assembly function.
- **Alternatives:** `GET /briefings/{run_id}` with server-side storage (extra route and state, evals can't use it); raising the event cap (violates the spec).

## D10. Gate summaries go in the session transcript and docs/orchestration/gate-summaries.md
- **Decision:** No Slack/email/other third-party message is sent for gate summaries; they are printed in the orchestrator session and appended to `docs/orchestration/gate-summaries.md`.
- **Why:** Writing to a real third-party account is on the "ask before" list and no destination was specified.
- **Alternatives:** Slack DM or Mail.app message (needs the user's confirmation of the target).
